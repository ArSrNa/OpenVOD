# ADR-0014：转码模板的存储位置

- 状态：已接受（2026-09-18，用户委托决策）
- 日期：2026-09-18
- 关联：ADR-0004、ADR-0008、intent.md「转码模板管理」

## 背景

intent 新增「转码模板管理」：模板包含编码器 / 分辨率 / 码率 / 帧率等参数、自适应分辨率上限约束、「保持原视频配置」（只加密流程）、加密开关与输出格式（v1 仅 HLS，选加密必须 HLS）。需要决定模板存放在哪里：数据库表、静态配置文件、环境变量或对象存储。候选位置的约束：模板是**部署者运行期数据**（每个部署者自定义，随管理台 CRUD 随时增删改），不是代码常量。

## 决策

**模板存共享数据库，新增 `transcode_templates` 表**；schema 真相源仍为 Prisma 双方言（ADR-0004，`task db:parity` 门禁）。

- **读写方**：管理端写（CRUD，挂 `/api/admin/[...path]` 会话守卫之下）；Worker 读（编码时展开为 ffmpeg argv 模板，ADR-0008 安全边界：argv 数组插值、绝不经 shell 拼接）。分发端（Go）不消费模板，读模型不含此表，受限 DB 账号无需授权。
- **字段初稿**（specification 细化）：`id`、`name`（唯一）、`description`、`keep_original`（bool，保持原视频配置，只加密流程）、`encrypt`（bool）、`format`（enum，v1 仅 `hls`）、`params`（JSON：codec、bitrate/CRF、fps、preset、分辨率——固定宽×高或自适应 `max_width`/`max_height` 约束）、`is_default`、时间戳。
- **校验与非法组合拒绝**：模板结构在 `packages/contracts` 定义 zod schema（管理端与 Worker 共用；Go 侧不消费，不进 quicktype 生成物）。`encrypt=true && format!=='hls'` 在模板保存与任务发起两层校验直接拒绝。
- **防漂移快照**：任务发起时把模板内容**快照**进 `transcode_jobs`（`template_snapshot` JSON 字段）；模板后续被修改 / 删除不影响已入队任务的可复现性。
- **种子数据**：seed 内置默认模板（对应 ADR-0008 默认 ladder 三档 + 一条 1080p 只加密模板），部署者开箱即用、可改可删。
- **删除保护**：有任务引用（含快照引用关系）时禁止硬删，采用软删 / 引用检查，specification 细化。

### 模板 → ffmpeg 命令编译（必经流程）

模板本身不可执行：**submit 转码任务后，模板必须编译为 ffmpeg 命令**，不存在绕过 ffmpeg 的路径。`keep_original`（只加密）同样走 ffmpeg：`-c copy` 重封装 + HLS 切片 +（可选）AES-128 加密，只是不重编码。

编译分两段，各自职责固定：

1. **submit 时（管理端）**：zod 校验 params、拒绝非法组合（`encrypt && format!=='hls'`）、模板快照进 `template_snapshot`。**此阶段不生成 argv**——源片分辨率 / 帧率 / 码率未知，自适应缩放（intent 规则 4）与三维度降级判定均无法换算；
2. **执行时（Worker，探测完成后）**：以 `media.probe`（ffprobe 实测源参数）+ `template_snapshot` 为唯一输入，由 **argv builder**（`apps/worker` 内白名单字段纯函数）编译最终 argv 数组：
   - 常规档：字段直接映射 + **三维度（分辨率 / 帧率 / 码率）降级判定**——低于源的维度按模板执行、不低于源的维度取源值；三维度均不低于源 → 该档跳过（不产 argv），全档跳过时由 `compileSourceMatched` 兜底产出一档（分辨率 / 帧率 / 码率保持原视频）；
   - 自适应档：按上限约束等比换算 scale 滤镜参数（如 2160×1080 + 宽≤1920 → scale=1920:960）；
   - `keep_original`：生成 `-c copy` remux / 切片命令；
   - `encrypt=true`：注入 key_info（密钥路径仅 Worker 注入，ADR-0006）。

编译器为**纯函数、可单测**（覆盖 intent 规则 1–4 的升格 / 持平 / 降帧率 / 降码率 / 自适应换算 / 全档兜底边界用例）；拼接只允许 argv 数组插值，**绝不经 shell**（ADR-0008 安全边界）。

### 执行判定规则的落位

intent.md 规则 1–4（只降不升、跳过判定、全档兜底、自适应等比缩放）的判定实现在 **Worker 认领任务后的探测阶段**：ffprobe 取源分辨率 / 帧率 / 码率（写入 `media.probe`）→ 逐档按三维度判定（低于源的维度按模板、不低于源的维度取源值；三维度均不低于源 → 跳过）→ 自适应约束等比换算 → 跳过档不产 argv；全档跳过时追加一档源规格兜底产出。判定在 Worker 而非管理端发起时做，保证以探测到的真实源参数为准。

### 补充（2026-09-18）：单次多选模板与同媒资并行

submit 支持一次选择**多个模板**（`template_ids[]`）：每个模板独立快照、各自入队一条 `transcode_jobs`，产物各落 `proceed/{mediaId}/{模板Id}/`（spec.md §1.3）。

因此「同一媒资同时只允许一个未终结任务」的约束收敛为「同一媒资 **+ 同一模板**」：不同模板产物分树存放、互不覆盖，可安全并行（spec.md §5.1）；同一模板重复发起仍在管理端 409 拒绝，避免同一子树并发互相覆盖。

执行侧：Worker 每轮只认领一个任务，单实例下同媒资各模板任务串行执行，从而保证加密任务共用同一份 CEK（避免并发 `generateMediaKey` 产出两把密钥、只有一把落库导致另一套产物不可解，ADR-0006 §4.2）；多实例横向扩展需在认领阶段补媒资级串行（v1 单 worker，属演进项）。

## 理由

- 管理台 CRUD 要求运行时可写 → 排除一切编译期 / 部署期载体；
- 与 `transcode_jobs` 同库：快照 + 引用完整性天然成立，模板变更可入 `audit_logs`；
- Prisma 双方言机制已由 ADR-0004 解决，**零新增基础设施**。

## 备选（否决 / 搁置）

- **环境变量 / 静态配置文件**（如 `config/templates.yml`）：改模板要重新发版，无法管理台 CRUD，多模板与默认档管理笨拙 —— 否决；
- **对象存储 JSON**（`metadata/` 分区）：无事务与引用完整性，列举 / 查询低效，且该分区语义是媒资产物而非平台配置 —— 否决；
- **`packages/shared` 常量硬编码**：只适合出厂默认值（作为 seed 数据源），不适合部署者自定义 —— 否决；
- **仅存 argv 字符串模板**（ADR-0008 原始设想）：注入风险需逐字段把关，改为存结构化 params JSON、由 Worker 白名单字段拼 argv —— 演进吸收。

## 后果与风险

- `params` JSON 在 SQLite 下为 TEXT：模板列表检索 / 过滤 v1 应用层实现（与 ADR-0004 JSON 风险一致）；
- 快照使每个 job 行增大（约 1KB 级），换取任务可复现与模板随时可改，可接受；
- Worker 判定逻辑（跳过 / 高位取源 / 自适应缩放 / 全档兜底）成为正确性关键路径，需单测覆盖 intent.md 规则 1–4 的边界用例（升格 / 持平 / 降帧率 / 降码率 / 自适应换算 / 全档跳过兜底）。
