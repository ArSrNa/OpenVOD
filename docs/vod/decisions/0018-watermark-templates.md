# ADR-0018：水印管理（模板落库 + watermark/ 分区 + ffmpeg 转码烧录）

- 状态：已接受（2026-10-02，用户定）；2026-10-05 实现落地并回写实现约束（§修订）
- 日期：2026-10-02（修订 2026-10-05）
- 关联：ADR-0005、ADR-0008、ADR-0014、intent.md「水印管理」、spec.md §10、open-questions #21 / #22

## 背景

intent 新增「水印管理」（2026-10-02）：转码时可以加上水印；水印在水印管理新建模板；模板参数含尺寸（显式像素宽高**或**占画面比例）、九宫格位置（左上 / 上居中 / 右上 / 左居中 / 居中 / 右居中 / 左下 / 下居中 / 右下）+ 对应 x / y 偏移、透明度、混合方式（**叠加** / **正常**）；同日增补**文字水印**（可直接设置常见字体、颜色、阴影、透明度，位置 / 尺寸 / 混合方式与图片一致）。硬性要求：水印图片存对象存储**独立目录**；水印模板**存数据库**；实现**尽量只使用 ffmpeg**。

需要决策的点：模板与图片资产的载体；与转码模板的关联方式（引用还是发起时选择）；烧录的滤镜实现路径（尤其「叠加」混合与文字渲染）；「只加密」流程的兼容性；图片资产的更新与删除语义。

## 决策

1. **水印模板落库**：新增 `watermark_templates` 表（Prisma 双方言 + parity 门禁，ADR-0004）：`id` / `name`（唯一）/ `description` / `type`（enum `image` | `text`）/ 图片元数据列（仅图片型）/ `params` JSON / 时间戳。管理端 CRUD、Worker 经**任务快照**只读消费——对齐 ADR-0014「结构化 params JSON + 快照防漂移」模式，不存 argv 字符串。参数 schema 以 zod 定义在 `packages/contracts`（管理端与 Worker 共用；不生成 Go，分发端不消费）。
2. **图片资产独立分区 `watermark/`**：键 `watermark/{模板ID}.{ext}`，**按水印模板 ID 组织**（非媒资 ID），是平台级模板资产而非媒资产物；ADR-0005 分区体系由四分区扩为**五分区**（media 列举与媒资删除均不触碰该分区）。文字水印无任何存储对象（仅落库参数）。
3. **关联方式（open-questions #21 收敛）**：`transcode_templates` 新增**可选** `watermark_id` 外键（一个转码模板至多关联一个水印模板；一个水印模板可被多个转码模板引用；应用层引用检查在前、DB `SetNull` 兜底）。submit 时把水印模板内容**快照**进 `transcode_jobs.template_snapshot.watermark`（id / name / type / params / 图片元数据），沿用 ADR-0014 快照机制；v1 **不提供**发起转码时临时改选水印（关联即模板属性，保持「模板 → 任务快照」单一来源）。`keep_original=true && watermark_id` 在模板保存与任务发起**两层校验拒绝**（烧录必须重编码，`-c copy` 无法叠加画面）。
4. **烧录只用 ffmpeg 原生滤镜**：统一「**全帧水印层 → 合成**」两段管线（细节见 spec §10.4）：
   - 水印层 L = 与该档输出同尺寸的全帧透明画布（`color=black@0.0`）上定位后的水印像素——图片走 `scale`（编译期数值）→ `format=rgba,colorchannelmixer=aa=<opacity>` → `overlay` 到画布；文字走 `drawtext`（`fontfile` / `fontsize` / `fontcolor` / `alpha` / `shadowcolor|shadowx|shadowy` / `x|y` 表达式，透明度烘进像素 alpha）；
   - **正常**：`[0:v][L]overlay`——标准 alpha 合成；
   - **叠加**：`[0:v]split` → `blend=all_mode=overlay` 全帧混合 → `[L]alphaextract` 取水印 alpha 作掩码 → `maskedmerge` 把混合**限制在水印像素内**（无水印区域保持原画面，边缘按 alpha 部分混合）——全帧无掩码 blend 会被透明黑底污染（overlay 模式对黑色顶层输出黑色），故掩码为必选项；
   - 滤镜链挂**每档变体缩放之后、编码与切片之前**；逐档按各自输出分辨率独立换算；与加密 / HLS 切片同一 ffmpeg 管线，不新增独立处理步骤；
   - 尺寸与（图片）坐标在 **argv 编译期以纯函数换算**——Worker 已知该档输出宽高（§5.4 判定结果）与快照参数（含上传时探测落库的 `image_width` / `image_height`）；文字坐标用 drawtext 运行期表达式（`text_w` / `text_h` 只有运行期可知）。argv 仍为白名单字段编译、数组插值，绝不经 shell（ADR-0008）；文字内容按 drawtext 转义规则统一纯函数转义。
5. **图片资产语义（open-questions #22 收敛）**：上传 / 替换为**覆盖式 PUT** 同一键（扩展名变化时删旧对象）；图片宽高在管理端上传时以 ffprobe 探测回填（损坏 / 伪扩展名在该步 400 暴露）；格式白名单 **png / jpg / webp 按内容识别**（透明通道仅 png / webp 保证）；上限 2 MiB。**删除保护**：被任一转码模板引用 → 409 拒绝硬删（先解除引用；已入队任务不受影响——快照自包含）；未被引用 → 先删对象再删行（幂等）。
6. **播放链路零改动**：水印随像素固化，分发端 / 播放端 / URL 签名 / 契约**零感知**；`hls_keys` 与水印无关（CEK 生成语义不变）；更新水印 = 重新转码。

## 修订（2026-10-05，实现落地后回写）

决策 1–6 不变，以下是**实现过程中标定出的技术约束**——它们是决策 4 的细化，不改变架构：

- **静态图片输入不加 `-loop 1`**：图片作为第二输入（单帧），画布 overlay 带 `shortest=1` 收敛为单帧，最终合成由 overlay 的 `eof_action=repeat` 铺满主输入时长。argv builder 固定此方式（决策 4 允许二选一）。
- **合成输出像素格式显式钉 `yuv420p`**：`overlay=format=auto` 会协商出 `yuva420p` / `yuv444p`（带 alpha 或 4:4:4），浪费码率且可能不被部分播放器接受。副作用：10-bit 源在带水印时被降到 8-bit（不带水印的模板不受影响），v1 接受。
- **叠加模式的 `blend` / `maskedmerge` 走 `gbrp`**（无 alpha 的平面 RGB）而非 `rgba`：rgba 下 alpha 平面会参与逐平面混合，实测（ffmpeg 6.1）得不到预期结果。画布内 alpha=0 区域恒为纯黑是 maskedmerge 正确性的前提。
- **有水印时改走 `-filter_complex` + `-map`，且音频必须显式 `-map 0:a?`**：`-vf` 无法表达「水印层 + 合成」两段；无水印的模板 argv 形态与既有实现逐字一致。**实测踩坑（2026-10-05）**：ffmpeg 一旦见到 `-map` 就对该输出文件关闭自动流选择——只映射视频滤镜输出会产出无声视频；上线后由真实媒资发现，已在两层端到端测试中以「去掉音频映射必红」锁死。
- **全档跳过时由 `compileSourceMatched` 兜底出一档并照常烧录**——不会出现「配了水印却没烧录」。
- **文字内容额外拒绝 ASCII 单引号 `'`**：ffmpeg 的滤镜 / 选项分词器（`av_get_token`）遇 `'` 即进入引号区且不处理反斜杠，字面 `'` 无法送达 `drawtext`（实测：任何转义写法都只会被丢弃）。其余特殊字符的转义规则（`\`→`\\`、`%`→`\\%`、`:`→`\:`、`,;[]`→`\c`，整串单引号包裹）已在 `packages/transcode/src/watermark.ts::escapeDrawtextText` 集中为纯函数并被单测锁定；裸 `%` 会触发 ffmpeg `Stray %` 且**整段文字不渲染**，是最容易踩的一条。
- **字体缺失必须显式自检**：`drawtext` 的 `fontfile` 不存在时 ffmpeg **不报错**，而是静默回退 fontconfig 默认字体——中文渲染成豆腐块而任务仍报成功。故：Worker 镜像构建期 `test -f` 三份字体（硬失败），Worker 启动时再自检一次并**告警不退出**（字体只影响用到文字水印的模板）。

## 备选（否决 / 搁置）

- **水印图片存 `cover/` 或 `metadata/` 分区**：语义混淆（封面是媒资产物、元数据是媒资数据），打乱媒资列举与统计口径 —— 否决，独立第五分区 `watermark/`；
- **模板 / 参数存对象存储 JSON**：无事务与引用完整性（同 ADR-0014 对对象存储模板的否决理由）—— 否决；
- **播放端 / 播放器侧动态叠加水印**：不解密内容即可被剥离，Safari 原生 HLS 无法保证覆盖层 —— 列入 intent 非目标（防录屏跑马灯同此）；
- **文字水印先用 ImageMagick / Pango 预渲染 PNG 再 overlay**：引入新依赖与临时文件管线，违背「尽量只用 ffmpeg」—— 否决，`drawtext` 原生承载（字体以内置清单解决）；
- **「叠加」混合直接全帧 blend（无掩码）**：透明底区域被污染 —— 否决，`alphaextract` 掩码 + `maskedmerge` 区域限制为必选；
- **水印参数进 quicktype Go 生成物**：分发端不消费 —— 按既有口径不进 `gen-json.ts` 清单（§7.8 规则）；
- **发起转码时临时选水印（不落模板）**：与「模板 → 快照」单一来源冲突，UI 与审计双份口径 —— v1 否决（演进再议）。

## 后果与风险

- **「叠加」模式性能**：全帧逐像素处理（rgba + blend + maskedmerge），转码耗时显著高于「正常」模式——v1 接受，由模板作者按需选择，任务日志可见；
- **字体可移植性**：`drawtext` 依赖字体文件——Worker 镜像必须内置字体（v1 固定 Noto CJK 清单，枚举落 `@openvod/shared`）；部署者自带字体列为演进项；
- **drawtext 转义**：文字内容含 `:` / `\` / `%` 等需按 ffmpeg 滤镜转义规则处理——统一转义纯函数 + 单测，绝不经 shell（ADR-0008）。**实测补充**：裸 `%` 会让整段文字不渲染（`Stray %`），字面单引号不可达（见修订）；
- 快照使 `transcode_jobs` 行再增约 0.5 KB 级（与 ADR-0014 同口径），可接受；
- argv builder 扩展为正确性关键路径：两类 × 两混合方式 × 九宫格（含负偏移 / 贴边 / 越界）× 等比与变形缩放 × opacity 0/100 边界需单测覆盖。
