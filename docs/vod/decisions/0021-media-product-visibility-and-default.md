# ADR-0021：媒资级转码产物展示与默认产物

- 状态：已接受（2026-11-15 用户定，同日实现）
- 日期：2026-11-15
- 关联：ADR-0004（数据库）、ADR-0010（分发端 API）、ADR-0011（受限账号）、ADR-0014（模板与产物布局）；spec.md §6.3 / §11.1

## 背景

1. 同一媒资可并存多套模板产物（`proceed/{id}/{templateId}/`，ADR-0014）。分发端 `play` 目前把**存储里实际存在的全部模板子树**作为 `templates[]` 返回，自动选择只认全局 `transcode_templates.is_default`（无默认则排序首项）。
2. 不同媒资的用途不同：同一套模板对 A 媒资是给 App 的清晰度选项，对 B 媒资可能只是内部留档。全局默认也无法表达「B 媒资进入时先放 720p」。
3. 需要管理端逐媒资设置「哪些产物给 SDK 看」与「进入时加载哪一套」，SDK 通过既有 `play` 响应拿到结果；不新增播放端接口，不改变现有鉴权链路。

## 决策

1. **存储**：`media.product_settings`（JSON，可空）：
   ```json
   { "visible_template_ids": ["c…", "c…"] | null, "default_template_id": "c…" | null }
   ```
   - `visible_template_ids = null` / 缺省 / 空数组 = 全部模板产物对播放端展示（与改造前行为一致，新产物默认可见）；
   - `default_template_id = null` = 无媒资级默认，回退全局默认模板 → 排序首项；
   - 不新建表：设置属于媒资，读路径已在 `media` 上（避免新表 + 受限账号授权 + 额外点查）。
2. **展示语义**：白名单只过滤分发端 `play` 的 `templates[]` 与**未指定 `template_id` 时的自动选择**。显式指定被隐藏的产物仍可播放（管理端「产物解密播放」预览、老客户端兼容），并随本次响应一并返回。**展示设置不是鉴权手段**：产物可访问性仍由 JWT / 播放会话 / URL 签名决定。
3. **默认优先级**：媒资级 `default_template_id`（必须在可见范围内）→ 全局 `transcode_templates.is_default` → 排序首项。响应 `templates[].is_default` 由分发端按这条链计算并**唯一打标**，不再直接透传模板行。
4. **一致性约束**：默认产物必须存在（当前有产物子树）且处于展示范围，否则保存返回 400；至少保留一套展示产物（空选择归一化为全部展示）。删除产物 / 模板不级联改设置：脏值在读路径降级（白名单无交集 → 全部展示；失效默认 → 回退全局），播放不中断。
5. **管理端**：`PATCH /api/admin/media/{id}/product-settings`（字段缺省 = 不修改；`null` = 全部展示 / 取消默认），落 `audit_logs`（`media.product_settings_update`）。「转码产物」抽屉逐套开关「播放端」并「设为默认」；详情接口的 `products[].isVisible` / `isDefault` 与 `productSettings` 供界面回填。
6. **分发端**：`store.MediaByID` 多读一列，`internal/server/product_settings.go` 手工解析（脏 JSON / 类型不符 → 默认值）；`resolveTemplate` 先过滤可见候选再选择。不新增表、不新增受限账号授权（ADR-0011）。
7. **契约**：`PlaybackTemplateDTO.is_default` 语义改为「有效默认产物」；管理端新增 `MediaProductSettingsDTO` / `UpdateMediaProductSettingsRequest`（仅管理端消费，不进 Go 生成清单）。

## 理由

- **逐媒资而非全局**：展示与默认是「这个媒资给谁看」的问题，模板级全局开关表达不了。
- **JSON 列而非关系表**：设置项固定为两个字段、随媒资生命周期整体读写；新表会引入迁移、受限账号授权与播放热路径的额外查询，收益不成比例。
- **白名单而非黑名单**：「展示哪些」是管理员主动挑选的清单，语义直观；空选择归一化为全部展示，避免误操作把媒资变成不可播。
- **展示不等于鉴权**：产物隐藏后仍要支持管理端预览与老客户端显式 `template_id`；若要做访问控制，应独立设计并复用现有会话 / 签名体系，不能混在展示设置里。
- **读路径容错**：脏设置 / 产物被删 / 模板行缺失都不能让 `play` 失败——可用性优先，与 `custom_data`、模板表查询失败降级的既有口径一致。

## 后果

- `media` 增加一列（expand 迁移 `20261115100000_media_product_settings`，MySQL；SQLite 走 `db push`），既有行为不变。
- `PlaybackTemplateDTO.is_default` 的含义从「模板行标记」变为「本媒资有效默认」，管理端 / SDK 展示文案无需改动，但不能再把多个模板同时标默认。
- 新增一个管理端端点与一次审计动作；分发端 `play` 多解析一个 JSON 字段，不增加查询次数（`media` 行本就读取）。
- 新产生的模板产物在设置了白名单的媒资上默认**不展示**（白名单语义）；管理员需在转码后开启，或在需要「全部展示」时清空白名单。

## 备选方案（未采用）

1. **新表 `media_product_settings`**：字段更规整、可加外键，但需要新迁移 + 分发端受限账号补授权 + `play` 额外查询，且设置与媒资严格一对一，关系表没有实际收益。
2. **黑名单 `hidden_template_ids`**：新增产物默认可见，运维更省心；但「展示哪些」需要反推，管理端开关与 API 语义不直观，最终选择显式白名单。
3. **隐藏产物拒绝显式播放**：能强化「SDK 拿不到就播不了」，但会打断管理端预览与已缓存 `template_id` 的老客户端；展示设置不承担鉴权职责，故不做。
4. **复用 `transcode_templates.is_default` 并允许每媒资复制模板**：模板数量随媒资膨胀，产物目录仍按模板 ID 组织，无法表达「同一模板在不同媒资下默认不同」。
