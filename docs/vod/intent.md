# Intent — OpenVOD 项目意图

- 日期：2026-09-17
- 状态：有效（随决策演进更新）

## 一句话

自建一套云点播（VOD）系统，覆盖「媒资入库 → 转码加密 → 元数据 / 字幕管理 → 带鉴权的分发播放」全链路，能够方便地部署到腾讯云 EdgeOne，或以 Docker 部署到腾讯云云函数（SCF）。

## 为什么做（背景）

- 业务方在多个 App 中有点播场景；直接使用云厂商 VOD 产品成本高、可控性差（转码参数、密钥、播放鉴权、数据都在平台侧）。
- 需要自持：媒资数据与自定义元数据、加密密钥、播放鉴权逻辑、字幕数据。
- 部署环境限定腾讯云生态：EdgeOne（Pages / CDN / Cloud Functions）或 SCF（容器化）；同时保留自托管 Docker Compose 退路。

## 核心使用流程（用户给出的应用逻辑，权威）

1. 播放端 App 的用户点播视频，App 调用**分发端** API（携带 JWT）；
2. 分发端校验 JWT 后，为该媒资签发**带签名的 CDN URL**（加密视频的 m3u8 与分片）；
3. 播放器请求分片播放，并调用**密钥 API** 获得播放密钥，解密播放（HLS AES-128）；
4. 元数据（标题、id、扩展自定义内容）与 WebVTT 字幕由分发端一并供给。

## 目标

### 功能目标

- **媒资管理**：上传、探测（ffprobe）、生命周期状态（就绪 / 转码中 / 失败 / 下架 / 删除）
- **转码**：自定义 ffmpeg 参数模板，输出 HLS（TS 容器；**是否 AES-128 加密由模板开关决定**，见「转码模板管理」与 spec.md §4），多码率 ABR
- **加密分发**：HLS AES-128；密钥分级（MK → **每媒资独立随机 CEK**，**不存在跨媒资共用的固定密钥**）；播放密钥受控下发（仅经鉴权后的密钥接口、响应 no-store，绝不入存储 / CDN / 日志）；URL 全链路签名
- **密钥管理**（管理端，只读 + 生命周期操作）：查看媒资加密状态（kid / method / mk_ver / 生成时间）、MK 版本与轮换、配合会话吊销；**任何页面 / 接口 / 日志都不提供明文密钥的查看或导出**（规范见 spec.md §4）
- **元数据**：系统元数据（时长 / 分辨率 / 编码等）+ 业务自定义数据（标题、id、任意 JSON 扩展）
- **字幕**：WebVTT 上传 / 编辑 / 管理；分发端按语言轨道下发
- **用户体系**：播放端用户（管理端维护，双端共享库）；分发端登录签发短期 JWT；播放会话可吊销
- **双端分离**：分发端（Go，以 API 为主）与管理端（TS）共用一个数据库
- **控制台总览**：管理端主页聚合展示媒资 / 转码任务 / 用户 / 存储用量等常用指标（详见下文「控制台总览」）
- **部署引导**：TS 引导脚本（TUI / 非交互双模式）为部署者生成各端 `.env`（详见下文「部署引导」）

### 存储与媒资标识（2026-09-18 用户定；规则权威定义见 spec.md §1）

- 对象存储资产统一放在一个**全局 root 前缀**下（`STORAGE_ROOT_PREFIX`，可不在桶根，支持与其它业务共享桶）；
- 资产按类别独立分区：`original/`（原视频）、`proceed/`（转码后文件）、`cover/`（封面、图片）、`metadata/`（元数据）；
- `proceed/` 采用**两级分组**：`proceed/{媒资id}/{模板id}/…`（2026-09-18 定）——目录名即模板 ID，因此「这份转码产物由哪个模板转出来」可直接从存储键读出；同一媒资允许多套模板产物并存，重转某个模板只影响该模板子树（权威定义见 spec.md §1.3）；
- 原视频上传后生成**唯一数字媒资 ID**（默认 8 位，`MEDIA_ID_LENGTH` 可配，保留前导零），是获取原视频、转码视频、封面图片资产、元数据的**唯一索引**。

### 媒资上传与管理（2026-09-18 用户定）

**上传（原视频入库）**

- 原视频统一上传到 `original/` 分区（S3 与 local 行为一致，键布局见 spec.md §1）；
- 上传成功即生成**唯一数字媒资 ID**，original 中的文件**直接以该 ID 命名**（`original/{id}.{ext}`）；
- ID 与 original 文件名一经生成**永不改变**：后续转码、重命名、字幕 / 封面 / 元数据等任何操作都不得影响；
- ID（即 original 文件名）**必须落库**，与 original 文件**唯一一一对应**；媒资的全部资产（proceed / cover / metadata / 字幕）均通过该 ID 索引。

**媒资管理操作（管理台）**

| 操作 | 说明 |
|---|---|
| 预览 | 弹窗直接播放 original 中的原视频 |
| 删除 | 删除媒资；存储与数据库的级联范围待 specification 细化（见 open-questions #13） |
| 重命名 | 仅修改数据库中的**展示名**，绝不改动 original 文件名与媒资 ID |
| 详情 | 弹窗展示媒资元数据 |

「更多」菜单（次级操作）：

| 操作 | 说明 |
|---|---|
| 转码 | 弹窗**多选**转码模板一并发起转码（每个模板各入队一条任务）；产物按模板落在 `proceed/{媒资id}/{模板id}/`（spec.md §1.3），列表/详情按模板分组展示「哪套产物出自哪个模板」（模板定义与执行规则见下文「转码模板管理」） |
| 字幕管理 | 多轨 WebVTT 字幕的增删改查（上传 / 更新元信息 / 覆盖文本 / 删除 / 设为默认），落 `proceed/{媒资id}/subtitles/{trackId}.vtt`（`trackId` = 服务端生成的轨道唯一 ID，同时是 `media_subtitles.id` 与存储文件名）并落 `media_subtitles` 表；语言按 BCP-47（如 `zh-CN` / `en-US`，输入兼容 `zh_CN` / `en_US` 写法、服务端归一化）。权威规则见 spec.md §7 |
| 生成元数据 | 为该媒资生成元数据到 `metadata/` 分区 |
| 设置封面 | 手动上传图片，或从原视频截帧（拖拽进度条选时间点取当前帧）作为封面，落该媒资的 `cover/{id}/` 目录 |

### 封面设置（媒资管理，2026-09-18 用户定）

媒资封面（poster）支持两种设置方式，落位与回写逻辑完全一致（权威规则见 spec.md §2.3）：

- **手动上传**：选择 / 拖拽本地图片文件直接上传（已实现）；
- **视频截帧**：弹窗播放 original 原视频，**拖拽进度条选择目标时间点**，截取当前帧画面作为封面；
  - 截帧在浏览器侧完成（`<video>` + canvas），不依赖 ffmpeg / Worker，服务端零新增负载；
  - 截帧产物编码为 JPEG 后走与手动上传相同的封面端点，服务端逻辑无差别；
  - s3 部署形态要求对象桶 CORS 允许管理端源站，否则浏览器侧帧导出被跨域策略阻断（此时回退手动上传）。

### 字幕管理（2026-09-20 用户定；权威规则见 spec.md §7）

- **入口**：侧边栏「字幕管理」（`/subtitles`：先选媒资，再管理该媒资的字幕）与媒资列表「更多 → 字幕管理」抽屉，两处共用同一轨道面板；
- **多轨**：一个媒资可挂多条 WebVTT 字幕轨道，按语言区分；每条轨道有独立的轨道唯一 ID（`trackId`，同时是 `media_subtitles.id` 与存储文件名，服务端生成）；
- **语言**：轨道必须声明语言标签（BCP-47，如 `zh-CN` / `en-US`）；输入兼容下划线写法（`zh_CN` / `en_US`），服务端归一化为连字符形态后存储与返回；**同一媒资内语言唯一**，避免播放端选轨歧义；
- **默认轨**：每媒资至多一条默认轨道；首条上传自动成为默认；
- **存储**：`proceed/{媒资id}/subtitles/{trackId}.vtt` —— `proceed/{id}/` 下的**保留段**，不属于任何模板产物，不受「按模板删除产物」影响（spec.md §1.3 / §7.2）；
- **格式**：存储**恒为 WebVTT**（对象键 `.vtt`）；上传 / 覆盖文本同时接受 **SubRip（`.srt`）**，服务端按**内容**识别并自动转为 VTT 后存储（时间轴逗号改点、补 `WEBVTT` 头、丢弃 SRT 定位参数；不并存 SRT 对象、不保存原文）；
- **校验**：服务端结构化校验（UTF-8 / `WEBVTT` 头 / cue 时间轴），**只校验不重排**（ADR-0009）；非法文件直接拒绝，不落库不落存储；
- **分发**：`GET /v1/media/{id}` 返回轨道元信息；`play` 一并返回带签名 token（`typ=v`）的字幕 URL（字幕鉴权必须走 URL query token —— Safari 原生 HLS 无法带请求头，而 token 需绑定可吊销的播放会话，故只能在会话上下文中签发）；`GET /v1/media/{id}/subtitles/{trackId}.vtt?t=` 取 VTT；播放端以**外挂轨道**方式集成（`<track>` / hls.js `addTextTrack`），不入 HLS 清单；
- **非目标**（v1）：字幕自动翻译 / 语音转写、烧录进画面、HLS 内嵌字幕轨（`EXT-X-MEDIA` + 分段 playlist）。

### 控制台总览（管理端主页，2026-09-18 用户定）

- 管理端登录后的主页（侧边栏「总览」，路由 `/`）为**控制台总览**：一屏展示常用运营指标，作为各功能模块的入口概览；
- 指标范围（首版）：**媒资总数**（含就绪 / 未入库拆分）、**进行中转码任务数**（转码中 / 探测中）、**播放端用户数**、**已用存储空间**（按 spec.md §1 的 `original/` `proceed/` `cover/` `metadata/` 四分区拆分并对照桶配额）、字幕文件数、转码产物数、元数据对象数、活跃播放会话数；
- 总览为**只读展示**，不在主页承载写操作；
- **真实数据接入进度（2026-09-20）**：**媒资总数**（含就绪 / 未入库拆分）、**进行中转码任务数**（排队 / 探测 / 转码 / 封装）与**播放端用户数**（总数 / 可用 / 已封禁）已接真实统计（`GET /api/admin/stats` 一次聚合，用户两次 DB COUNT）；存储用量 / 字幕 / 产物 / 元数据 / 活跃会话仍为 mock 占位，随 M4 与存储列举能力落地后在同一端点扩展，页面结构不变。

### 用户管理（播放端用户，2026-09-20；权威规则见 spec.md §2.1.1）

管理台对**播放端用户**（`users` 表，ADR-0004）提供增删改查；与登录控制台的管理员账号（`admin_users` + better-auth）是两套体系。

- **新建**：用户名 + 口令（bcrypt 摘要后入库，管理端不可回看口令），可设展示名与并发上限；默认可用；
- **编辑**：展示名、状态（可用 / 封禁）、并发上限（`0` = 不限制）；**用户名创建后不可修改**（改名 = 新建 + 删除）；
- **封禁**：立即拒绝该用户登录并**吊销其全部未过期播放会话**；会话计数归零。**删除**则级联删除会话记录（不可恢复），故一般处置优先用封禁；
- **重置口令**：凭据变更后同样**吊销全部未过期会话**（旧 JWT 不再可用）；
- **吊销会话**：手动踢下线（不封禁账号，用户可重新登录）。

### 系统设置（2026-09-20 用户定；权威规则见 spec.md §2.1.2）

控制台「系统设置」二级菜单（按域拆子页：播放 / 存储 / 安全）承载**运行时可调**的部署配置；设置项**落库存储**（`system_settings` key-value），免重启生效、变更加审计——不再依赖「改 env + 重启」。

分层原则（用户定）：**启动必需、敏感材料、分发端热路径三类保留环境变量**，其余运行时非敏感业务项逐步落库：

- **env 保留**：数据库连接、密钥材料（MK / URL 签名）、S3 凭据、分发端参数（ADR-0006 / 0011）；
- **落库**：播放域名 `playback_base_url`（已实现——覆盖 `DELIVERY_PUBLIC_BASE_URL`，清单 / 密钥 / 字幕基址，分发端 60s 缓存读取）等非敏感控制面项；
- **兜底**：设置读取失败一律回退 env / 内置默认，DB 故障不阻塞播放链路；
- **文件形态（2026-09-20 用户定）**：文件配置统一用 **env**（平台 Secret 注入 / Compose `env_file` / serverless 控制台全是 env 语义），**不引入 yaml 等结构化配置文件**——避免双语言两份解析、容器文件挂载与密钥注入模板化成本。

### 部署引导（.env 生成脚本，2026-09-20 用户定）

**背景**：交付到部署者手上时，管理端与分发端已是**两个独立的 app / 容器镜像**（外加 Worker 常驻容器），各自消费不同的 env 域（shared / admin / worker / delivery）；部署者不应手工编辑 `.env`——需要一个 **TS 引导脚本**交互式生成配置。

- **形态**：TS 脚本（Bun 运行）+ 交互式 TUI 问答；同时支持**非交互模式**（参数 / JSON 全量传入，供 CI 与 Compose 自动化）；
- **职责**：
  - 按端生成 `.env`（分段与 `.env.example` 的 shared / admin / worker / delivery 注释域一致，可整份或按端单独输出）；
  - **自动生成随机敏感材料**：`MASTER_KEYS`、`URL_SIGN_KEY_HEX`、`BETTER_AUTH_SECRET`、播放预览账号口令（openssl 级随机，不手填）；
  - 数据库向导：MySQL / SQLite 二选一（SQLite 提示后续 `db:push`）；存储向导：local / S3（MinIO / COS 参数与寻址风格）；
  - 端点向导：`DELIVERY_PUBLIC_BASE_URL`、`ADMIN_BASE_URL`（CNB 预览域名自动识别逻辑保持）；
  - 可选连通性校验（DB 可达 / 分发端探测），失败给排查提示；
- **边界**：不替代部署平台 Secret 管理（生产密钥注入仍走 env 语义，脚本产物可只作本地 / 自托管起点）；不负责容器编排（compose 示例按 ADR-0011 交付物另行提供）；生成的 `.env` 不入库；
- **排期**：随产品化里程碑落地（ADR-0011 交付物「部署文档 + compose 示例」的配套），specification 时在 spec.md 补权威规则。


### 转码模板管理（2026-09-18 用户定；存储位置已决策：ADR-0014）

管理台提供**转码模板**的增删改查；媒资发起转码时（「更多 → 转码」弹窗）选择模板执行。模板决定输出的视频参数、输出格式与是否加密。

**模板内容**

- 视频参数：编码器（从 ffmpeg 支持的编码器列表选择，v1 主用 **x264 / x265**，即 libx264 / libx265）、分辨率、码率（或 CRF）、帧率、preset 等；
- **保持原视频配置**：模板可声明不重编码，仅做 HLS 封装（+ 可选加密），用于**只加密流程**（省转码成本，源参数原样输出）；
- **是否加密**：**开关项，不承载密钥选择**——开启后由 Worker 在执行任务时为该媒资随机生成 CEK → MK 封装落 `hls_keys` → HLS AES-128（key_info）加密分片；管理端**不可指定、复用或替换密钥**（理由：共享密钥会把泄露爆炸半径放大到全部媒资，规范见 spec.md §4）；
- 输出格式：v1 统一为 **M3U8（HLS）**；其他格式（MP4 直出等）后续以新增 intent 扩展。硬约束：**选择了加密，输出必须为 HLS**（模板校验层面直接拒绝非法组合，不进入任务队列）。

**模板 → ffmpeg 命令（必经流程）**：模板本身不可执行，submit 转码任务后必须编译为 ffmpeg 命令——含「保持原视频配置」（`-c copy` 重封装 + 切片 + 可选加密）。submit 时仅做校验与快照（源参数未知，不产 argv）；实际 argv 由 Worker 探测后以「实测源参数 + 模板快照」为输入编译，详见 ADR-0014。

**转码执行判定规则（是否执行 / 跳过某档；2026-09-18 修订，判定维度 = 分辨率 / 帧率 / 码率）**

1. **只降不升、高位取源**：模板档位与源片逐维度比较——**低于**源的维度按模板执行（真降级）；**不低于**源的维度一律取原视频值（不放大、不补帧、不抬码率）：
   - 源 1920×1080@60fps、模板 3840×2160@60fps：分辨率升格 → 取源 1920×1080（不放大）；
   - 源 1920×1080@60fps、模板 1920×1080@30fps：帧率降级 → 执行（`-r 30`），分辨率取源；
   - 源 8Mbps、模板 3Mbps：码率降级 → 执行（`-b:v 3000k`），分辨率 / 帧率取源；
   - 源与模板规格完全相同（如 1920×1080@60fps → 1920×1080@60fps）：**跳过**（三维度均无降级，无重编码意义）。
2. **跳过判定**：分辨率、帧率、码率**三维度全部不低于源** → 该档跳过（不产 argv）。
3. **全档跳过兜底（不空手失败）**：若某模板**所有档位**均被判跳过，仍按模板产出**一档**——编码器 / preset / CRF / 加密按模板，**分辨率、帧率、码率保持原视频**（「既然配置并发起了转码，就必须出片」；不再出现「所有档位均被跳过，无可用输出」）。
4. **自适应分辨率**：分辨率可不写死为固定宽×高，以**上限约束**表达（如「宽度不超过 1920」）：
   - 例：源 2160×1080，约束「宽 ≤1920」→ 等比缩放为 **1920×960**（1920 × 1080 / (2160/1920)）；
   - 源尺寸已在约束内（如源宽 1600 ≤ 1920）→ 分辨率维度取源值（不缩放），是否执行由三维度合并判定（open-questions #18）；
   - 多维约束（宽与高同时设上限）时按更严格者等比缩放，保持宽高比。

### 非功能目标

- 一次开发、多目标部署：EdgeOne Pages Cloud Functions（Go）、SCF Web 函数（容器）、自托管 Compose
- **数据库与对象存储可插拔**：OpenVOD 面向多部署者，部署者可自带数据库（公网可达的 MySQL / SQLite）与 S3 兼容存储，不绑定腾讯云内网（分发端在 EdgeOne CF 与 SCF 容器间自由选择）
- 密钥等敏感材料**绝不落 CDN / 边缘缓存**（P0 纪律，CI 断言）
- 热路径（清单 / 分片 / 密钥）验签自包含，不依赖重查询

## 非目标（v1 明确不做）

- DRM（Widevine / FairPlay / PlayReady）与 license server —— 演进路径见 ADR-0006
- **固定密钥 / 跨媒资共享密钥 / 管理端自定义密钥**：模板的加密开关不承载密钥选择，密钥永远按媒资随机生成（spec.md §4.1）——避免单点泄露放大到全部媒资且无法轮换收敛
- **明文密钥的查看 / 导出**：管理端无此入口；密钥唯一出口是分发端鉴权后的密钥接口（token 绑定 mid + sid，no-store）
- 直播 / 低延迟直播 / 实时转码
- 视频剪辑与时间线编辑
- 每用户独立的分片加密（ADR-0006 权衡）
- 多租户 SaaS 化（表结构不引入 tenant 维度）
- 字幕自动翻译 / 语音转写
- 非 HLS 输出格式（MP4 等）——后续以新增 intent 扩展
